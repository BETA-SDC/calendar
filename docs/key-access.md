# 内部和待定事件的密码访问

事件有两个独立标签：

| 可见范围 | 计划事件 | 待定事件 |
| --- | --- | --- |
| 公开 | 无需密码 | 需要密码 |
| 内部 | 需要密码 | 需要密码 |

范围由 `public/`、`internal/` 目录管理；状态使用标准 ICS
`STATUS:CONFIRMED` / `STATUS:TENTATIVE`。旧文件没有 `STATUS` 时按计划
事件处理，不修改 UID、提醒或时间。取消事件保留 `STATUS:CANCELLED`，
仍归入计划分类。

## 轻量密码拦截

访问密码为 `betasdc`，在 `web/access.js` 中设置。订阅页和单事件页
共用同一逻辑：

- 未解锁时，只显示公开计划事件，内部、待定及“全部状态”提示输入密码。
- “全部可访问活动”在计划状态下只包含当前允许访问的事件；选择
  “全部状态”时必须先解锁，不显示部分结果或提供订阅链接。
- 输入正确密码后，开放内部、待定及全部状态的事件和订阅、下载、复制链接。
- 解锁标记保存在 `sessionStorage` 中，同一浏览器标签页内导航和刷新
  都保持解锁；新标签页通常需要重新输入，浏览器复制标签页可能复制会话。
- 点击“锁定”后清除解锁状态，重新隐藏内部和待定事件。
- 浏览器禁用存储时，当前页面仍能解锁，但跨页需要再次输入密码。

这是为非敏感信息设置的前端访问门槛。密码在前端源码中可见，原始 JSON、
ICS 和公开仓库内容仍可直接访问。已有订阅不会因为页面重新锁定而失效。
当前版本没有服务端鉴权，也没有加密或撤销订阅 token。

## 构建和管理

默认构建及 Pages 工作流发布全部事件，由页面进行密码拦截。既有公开、
内部和全部活动订阅 URL 保持不变。CLI 的 `list/show/add/import/update`
是本地管理命令，不验证网页密码。

如果以后希望完全不发布受限内容，可使用：

```bash
./bin/calendar build --public-only --json
python scripts/build_feeds.py --output site --public-only
```

该模式从全部聚合订阅、年份/月度订阅、JSON 索引和单事件 ICS 中排除
内部以及待定事件，但不能隐藏公开仓库中已有的源文件和 Git 历史。

如果未来出现敏感信息，再将受限数据迁到私有存储，并增加服务端鉴权；
网页可使用密码换取会话，日历订阅可使用独立、可撤销的 token 链接。
